# `10-retrieval-request.json`

This file is the operational retrieval plan for `nft-BAYC-real`.

It is generated from the discovery brief and used to produce the concrete retrieval prompts for Etherscan and Dune.

## Role

- `05-discovery-brief.json` defines the high-level discovery goal
- `10-retrieval-request.json` translates that goal into a concrete retrieval scope
- `20-rendered-retrieval-prompts.json` renders the actual prompt payloads

## Required fields

- `experiment_id`
  Must match `experiment.json`.

- `objective`
  Experiment objective kept for traceability.

- `target.chain`
  Chain used for retrieval.

- `target.contract_address`
  Concrete BAYC contract address.

- `target.contract_label`
  Contract label used in prompts and review.

- `etherscan_request.template`
  Etherscan template path.

- `etherscan_request.required_outputs`
  Structured list of expected Etherscan-side outputs.

- `dune_request.template`
  Dune template path.

- `dune_request.analysis_window`
  Retrieval window for trend metrics.

- `dune_request.target_metrics`
  Metrics the Dune retrieval must prioritize.

## Optional fields

- `discovery_goal`
  Expanded discovery rationale derived from the discovery brief.

## Who writes it

- first generated by `prepare:retrieval-request`
- then reviewed and optionally edited by a human

## Who uses it

- `render:retrieval-prompts`
- humans preparing raw MCP capture files

## When to edit it

Edit it when:

- the target contract is wrong
- the inferred metrics are wrong
- the retrieval window is too narrow or too broad
- you need more or fewer Etherscan-side outputs before collecting evidence
